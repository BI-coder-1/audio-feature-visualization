# 交互式网页说明

## 1. 功能定位

网页是现有课程项目的交互入口，不另写一套重复算法。用户可以选择单文件深度分析或双文件特征比较。Flask 接收 WAV 后，调用 `src` 中的读取、基础特征、短时特征、频谱统计、MFCC、FFT 和 STFT 函数。

## 2. 启动方法

```powershell
python -m web_app
```

浏览器打开 `http://127.0.0.1:5000`。默认只监听本机地址，局域网和互联网中的其他设备不能直接访问。

## 3. 一次请求的处理顺序

1. 浏览器使用 `multipart/form-data` 上传 WAV 文件。
2. Flask 检查是否选择文件、扩展名是否为 `.wav`、文件是否超过 12 MB。
3. `TemporaryDirectory` 创建只服务于本次请求的临时目录。
4. `load_wav()` 读取音频并生成 `AudioSample` 对象。
5. `extract_basic_features()` 计算八项基础时域特征。
6. `extract_advanced_summary()` 计算短时能量、过零率和五项频谱统计量。
7. `compute_mfcc()` 用 25 ms 帧、10 ms 帧移、26 个 Mel 滤波器计算 13 维 MFCC。
8. 三个绘图函数分别生成波形/频谱、STFT 和进阶特征四联图。
9. 特征字典转换为 CSV data URL，用户可直接下载结果。
10. 图片、音频和 CSV 被 Base64 编码后嵌入结果页面。
11. 离开 `with` 代码块后，临时目录及上传文件自动删除。

双文件比较会对两个文件执行同一套基础与进阶特征计算，避免使用不同尺度或不同算法造成不公平比较。

## 4. 为什么使用 Base64

浏览器通常通过 URL 请求图片和音频。但本项目不保存用户文件，因此不能在分析结束后继续提供一个磁盘文件 URL。Base64 会把二进制内容转换成文本并放进 HTML 的 data URL，页面拿到响应后即可直接显示。代价是响应体会变大，所以网页设置了 12 MB 的请求总量上限。

## 5. 安全边界

- 只接受 `.wav` 扩展名，文件内容仍由 SciPy 验证。
- `secure_filename()` 清理文件名，避免用户文件名被解释为目录路径。
- 上传内容写入系统临时目录，不写入项目的 `data`、`samples` 或 `results`。
- 默认只监听 `127.0.0.1`，适合课程演示，不等同于生产服务器。

## 6. 页面设计说明

页面借鉴高校官网常见的信息层级：顶部辅助导航、深蓝色主导航、宽幅主视觉和分区内容模块。项目没有复制山西大学校徽、照片或其他官方素材，也不代表山西大学官方网站。
